# Командная строка yam

```text
yam [ГЛОБАЛЬНЫЕ ФЛАГИ] <команда> [аргументы]
```

Источник правды — `src/bin/yam.rs`. Любая ошибка завершает `yam` ненулевым
кодом, сообщение идёт в stderr.

## Глобальные флаги

| Флаг | Переменная | По умолчанию | Назначение |
| --- | --- | --- | --- |
| `--platform <id>` | `YAM_PLATFORM` | — (обязателен) | ID профиля платформы, например `yandexmicro`. См. [PLATFORMS.md](PLATFORMS.md). |
| `--profiles <каталог>` | `YAM_PROFILES` | `platforms` | Каталог с YAML-профилями (`<id>.yaml`); путь относительный к текущему каталогу. |
| `--root <каталог>` | `YAM_ROOT` | `paths.root` из профиля | Корень YAM целиком: пакеты, база, настройки реестров и кэш загрузок. Например, для проверки без колонки. |
| `--registry <имя>` | — | `official` | Реестр для `install <имя>`, `search`, `info`, `plan`. |

`--platform` обязателен для всех команд, включая `update` и `registry`:
профиль загружается до разбора команды.

На колонках установщик кладёт обёртку `$YAM_ROOT/bin/yam-run` (по умолчанию
`/data/yam/bin/yam-run`), которая экспортирует `YAM_PLATFORM`,
`YAM_PROFILES=$YAM_ROOT/platforms` и `YAM_ROOT` и запускает
`$YAM_ROOT/bin/yam`. Установщик также создаёт `/usr/bin/yam` и добавляет
`$YAM_ROOT/bin` в `PATH`, поэтому на любой поддерживаемой станции достаточно
написать:

```sh
yam list
yam update
```

## Пакеты

Пакеты `.yampkg` собирает PC-инструмент `yam-publish pack`, а не `yam`; см.
[PACKAGING.md](PACKAGING.md) и [PUBLISHING.md](PUBLISHING.md). Эксклюзивный
`flock` на `$YAM_RUN/yam.lock` берут только `install`, `remove` и `repair`;
остальные команды открывают базу без блокировки.

### `install <пакет> [-y|--yes]`

Устанавливает пакет. Аргумент трактуется так:

- если по этому пути существует файл — это локальный `.yampkg`;
- иначе это имя в реестре (`--registry`): `имя` или `имя@версия`. Короткое имя
  без `/` разрешается в уже установленного провайдера или в единственный
  официальный `yam/…` (`yam/<имя>` либо пакет с `provides`); иначе нужно
  указать полное имя.

Для реестра сначала строится граф `depends`, затем все артефакты скачиваются
в `cache/registry-<uuid>` корня и ставятся по порядку. Уже установленные
версии пропускаются. Граф ставится не атомарно: если установка любого члена
падает, YAM пытается удалить пакеты, впервые поставленные в этом запуске
(ошибки удаления игнорируются); пакеты, обновлённые раньше в этом графе, не
откатываются. `recommends` не
устанавливаются. Если запрошенный пакет уже установлен в выбранной версии
(или отсутствует в плане), команда завершается ошибкой.

Проверки при установке: цель пакета (`target`) равна `any` или совпадает с
платформой, архитектура совпадает, нет конфликтов. Подпись индекса и SHA-256
архива проверяются только при установке из реестра; у локального `.yampkg`
подписи нет. Флаг `-y` нужен, когда
пакет:

- заменяет (`replaces`) установленные пакеты — они будут удалены;
- запрашивает пакеты Entware.

Без `-y` команда отказывается и сообщает, что именно будет затронуто. Если
предыдущая транзакция не завершилась, установка отказывает и требует
`yam repair`.

Вывод: `Installed <имя> <версия> for <цель>.`

```sh
yam install namespace/package
yam install namespace/package@1.2.0
yam install --yes ./package.yampkg
```

### `remove <имя>`

Удаляет установленный пакет по полному имени `namespace/name`. Проверяет
пакеты, зависящие от удаляемого. Отказывает при незавершённой транзакции
(`yam repair`). Вывод: `Removed <имя>.`

### `list`

Установленные пакеты, по одному в строке, через табуляцию:
`имя<TAB>версия<TAB>цель`. Сортировка по имени.

### `files <имя>`

Пути файлов пакета (относительно корня), по одному в строке.

### `which <путь>`

Печатает пакет-владельца пути из общего дерева (`bin/…`, `share/…`),
например `yam which bin/tool`. Если путь не принадлежит пакету YAM,
завершается ошибкой `<путь> is not owned by a YAM package`.

## Состояние и обслуживание

### `doctor`

Проверяет состояние только на чтение. Находит:

- ссылки из базы, которых нет или которые указывают не туда;
- символические ссылки на `pkgs/` в `bin/` и `share/`, не записанные в базе;
- каталоги в `pkgs/`, которых нет в базе;
- устаревшие каталоги версий;
- пакеты, записанные в базе, но без каталога с содержимым.

При порядке печатает `Состояние пакетов в порядке.`. Иначе каждая проблема
идёт в stderr строкой `problem: …`, код возврата ненулевой.

### `repair`

Восстанавливает ссылки общего дерева, записанные в базе YAM. Чужие файлы не
удаляются и не заменяются; при невозможности чинить (нет содержимого пакета,
на месте ссылки обычный файл или чужая ссылка) завершается ошибкой. Также
снимает отметку незавершённой транзакции (`db/transaction.json`), после чего
`install` и `remove` снова работают. Печатает `Repaired <путь>.` на каждое
исправление или `Nothing to repair.`.

### `update`

Обновляет сам `yam` из GitHub Releases.

1. Доступно только в сборках для Linux aarch64 (`aarch64-unknown-linux-musl`)
   и Linux armv7 (`armv7-unknown-linux-musleabihf`) и только при запуске
   установленного файла с именем `yam`.
2. Берёт последний опубликованный (не draft и не prerelease) релиз с тегом
   `yam-v…`, скачивает `yam-update-<target>.json` и
   `yam-update-<target>.json.sig` для своей сборки.
3. Проверяет подпись Ed25519 манифеста ключом `YAM_UPDATE_PUBLIC_KEY`,
   зашитым при сборке. Сборка без ключа обновляться не может.
4. Если версия совпадает с текущей, печатает
   `Уже установлена актуальная версия <версия>.`.
5. Иначе скачивает бинарник, сверяет размер и SHA-256 с манифестом, затем
   записывает его во временный файл рядом с исполняемым, переименовывает
   поверх и печатает
   `Установлено обновление <версия>.`.

Проверку обновления при загрузке на Micro делает загрузочный скрипт
`/etc/init.d/S99yam` (см. [README](../README.md#обновление)).

## Entware

Entware — внешний менеджер пакетов `opkg`; путь берётся из `entware.opkg`
профиля платформы.

| Команда | Действие |
| --- | --- |
| `entware status` | Печатает `available`, если `opkg` из профиля существует, иначе `unavailable`. |
| `entware list` | Вывод `opkg list-installed`. Ошибка, если для платформы Entware не настроен или `opkg` завершился неуспешно. |

## Службы

### `service list`

Объявления служб установленных пакетов, через табуляцию:
`пакет/служба<TAB>enabled|disabled<TAB>аргументы exec через пробел`. Службы только хранятся в базе
и показываются здесь: запуска и наблюдения за процессами нет.

## Реестры

Настройка реестров хранится в `db/registries.yaml` корня пакетов и **по
умолчанию пуста**: реестр `official` нужно добавить самостоятельно, иначе
`install <имя>`, `search`, `info` и `plan` вернут `registry not configured`.
Формат реестра и подписи — [REGISTRY.md](REGISTRY.md).

### `registry list`

Настроенные реестры: `имя<TAB>url`.

### `registry add <имя> <url> --key <ключ>`

Добавляет или заменяет реестр. Имя — `a-z`, `0-9`, `-`; URL только `https`.
`--key` обязателен; при добавлении проверяется лишь префикс `ed25519:`, сам
ключ проверяется при первой проверке подписи. Конечные `/` в URL отбрасываются. Вывод:
`Added registry <имя>.`

```sh
yam registry add official https://example.org/registry --key ed25519:BASE64KEY
```

### `registry remove <имя>`

Удаляет реестр; ошибка `registry not configured`, если такого нет. Вывод:
`Removed registry <имя>.`

### `search <запрос>`

Ищет в каталоге выбранного реестра. Подходят пакеты, у которых запрос входит
в имя или в ключевое слово (с учётом регистра) либо в описание (без учёта
регистра). Вывод: `имя<TAB>последняя версия<TAB>описание`.

### `info <имя>`

Печатает индекс пакета из реестра в виде JSON с отступами.

### `plan <пакет>`

Разрешает граф зависимостей в реестре (`имя` или `имя@версия`) с учётом
установленных пакетов и профиля. Загружает подписанные индексы реестра, но не
скачивает архивы пакетов и ничего не устанавливает; как и другие команды, при
первом запуске создаёт каталоги YAM и `db/state.sqlite3`.
Вывод: `имя<TAB>версия<TAB>url артефакта` на каждый пакет графа.
